# AstraMesh Cryptography & Security Model

AstraMesh guarantees End-to-End Encryption (E2EE), Forward Secrecy (PFS), Post-Compromise Security (PCS), Anti-Replay protection, and metadata privacy without depending on centralized PKI or certificate authorities.

---

## 1. Cryptographic Primitives

- **Asymmetric Curve**: NIST P-256 (`secp256r1`) ECDH key agreement (`AstraKeyAgreement`).
- **Key Derivation**: RFC 5869 HKDF using HMAC-SHA256 (`AstraHkdf`).
- **Authenticated Encryption**: AES-256-GCM (`AstraAead`) with 12-byte cryptographically secure random IVs and 128-bit authentication tags.
- **Node ID Anonymity**: Rotating ephemeral identifiers generated by hashing the root private key with 15-minute epoch counters (`EphemeralIdDeriver`).

---

## 2. Double Ratchet Engine (`AstraRatchetEngine`)

Communication between paired peers employs a two-tier ratchet protocol:
1. **DH Ratchet**: Executes on every conversational turn when a new public key is received from the remote peer, advancing the Root Key ($RK$) and creating new Chain Keys ($CK_s$, $CK_r$).
2. **Symmetric-Key Ratchet**: Advances within each message transmission, deriving single-use Message Keys ($MK$) from the current Chain Key:
   $$MK = \text{HMAC-SHA256}(CK, \text{"MessageKey"})$$
   $$CK' = \text{HMAC-SHA256}(CK, \text{"ChainAdvance"})$$
3. **Out-of-Order Message Handling**: Skipped message keys are cached in memory and database up to a maximum limit (1000 keys) to allow decryption of packets that arrived out-of-order over multi-hop mesh paths.

---

## 3. Sliding Window Anti-Replay Protection

To prevent malicious replay attacks in hostile radio environments:
- The receiver maintains a **64-bit sliding window bitmap** (`ReplayProtectionWindow`).
- Incoming sequence numbers $< (\text{MaxSeen} - 64)$ are immediately rejected.
- Incoming sequence numbers within the $[ \text{MaxSeen} - 64, \text{MaxSeen} ]$ range are checked against the bitmap:
  - If bit is set: Packet is rejected as duplicate/replayed.
  - If bit is clear: Bit is set and packet is decrypted.
- Incoming sequence numbers $> \text{MaxSeen}$ advance the window, shifting the bitmap.

---

## 4. Short Authentication String (SAS) QR Pairing

Peers pair out-of-band using dynamic QR codes (`QrPairingCodec`):
- QR code payload encodes:
  - Public Key (65 bytes uncompressed)
  - Display Name
  - Timestamp
- A 6-digit Short Authentication String (SAS) fingerprint is derived via HKDF:
  $$\text{Fingerprint} = \text{HKDF}(\text{RootSecret}, \text{"AstraMesh-SAS"}, 4) \pmod{1000000}$$
- Users visually compare the 6-digit SAS code on both screens to detect Man-In-The-Middle (MITM) attacks.

---

## 5. Cryptographic Panic Data Wipe

In high-risk scenarios, users can trigger the panic wipe function (`SettingsViewModel.wipeAllData`):
1. Overwrites in-memory private key material via `java.security.KeyStore` / `Destroyable.destroy()`.
2. Clears all Room SQLite tables (`chats`, `messages`, `peers`, `routes`, `session_keys`, `audit_logs`).
3. Re-generates a fresh, unlinked identity keypair and restarts the mesh stack.
